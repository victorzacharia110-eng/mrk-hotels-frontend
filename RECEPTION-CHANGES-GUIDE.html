MRK Hotels

RECEPTION PANEL CHANGES GUIDE

For Non-Technical Staff

This guide answers every request in the client document “RECEPTIONIST PANEL DESIGN AND LOGIC TO BE UPDATED”. For each request you will see the Problem (written exactly as in the client PDF), the Solution delivered, the Status, and Where to find it in the system. All changes are visible to the reception / front-desk team.

1. ROOMS PAGE — INVENTORY SUMMARY & CALENDAR

“When receptionist clicks ROOMs the default page is INVENTORY currently in MRK the inventory page is a list of rooms registered … By (room type) … bottom totals SOLD ROOMS / ROOMS AVAILABLE / TOTAL ROOMS … a CALENDAR-themed page … the business date on the calendar page … should be the first column after room number.”
The Inventory tab now opens as a summary, not a plain list. It groups the rooms by room type (Standard, Deluxe, Suite, Executive …) and shows a totals strip at the bottom with SOLD ROOMS, ROOMS AVAILABLE and TOTAL ROOMS. Below the summary there is a new Availability Calendar — rooms down the side, days across — whose first column is the business date. The full room register is still available on its own tab for anyone who needs the plain list.
Status: DONE
→ Dashboard > ROOMs > Inventory (Summary Totals + Availability Calendar)

2. DASHBOARD ROOMS ROWS SPACING

“When receptionist clicks ROOMs the default page is INVENTORY … DASHBOARD ROOMS ROWS SPACING — the rows are too tall; reduce the spacing.”
The room rows on the Dashboard chart were tightened so more rooms fit on one screen. The room number, status dot and stay bars all sit closer together and the calendar reads with less empty space.
Status: DONE
→ Dashboard > Rooms Chart (Tighter Rows)

3. BUSINESS DATE

“Instead of writing the word BUSINESS DATE replace it with the actual BUSINESS DATE in numbers the business date should be clickable as well meaning by clicking it opens a calendar … the business date on the calendar page of the dashboard should be the first column after room number.”
The toolbar now shows the real business date in numbers (for example 09/10/2026) instead of the words “Business Date”. The figure is clickable — it opens a calendar so the desk can jump straight to any day. On the chart itself the business date is the first day column, right after the room number.
Status: DONE
→ Dashboard > Top Toolbar > Business Date Figure (Click To Open Calendar)

4. NUMBER OF GUESTS (AND BOOKING TYPE)

“Upon registering a guest there is a REQUIREMENT to fill which type of booking it is: SINGLE BOOKING = 1 GUEST, COUPLE BOOKING = 2 GUESTS, FAMILY BOOKING = 3 – 5 GUESTS. Replace the profile name of the LOGGED IN USER with the TOTAL number of GUESTS from all checked in guests in the house of the particular BUSINESS DATE.”
The booking form offers a Booking Type (Single = 1 guest, Couple = 2 guests, Family = 3–5 guests, Group) which sets the guest head-count. On the Dashboard the logged-in user’s name was replaced by the total number of guests staying on the business date, so the desk can see the house count at a glance.
Status: DONE
→ Dashboard > + New Booking > Booking Type  |  Dashboard > Top Bar > Guests In House Count

5. TOP PANEL AND SIDE BAR REARRANGEMENT

“The top panel has the hotel info; should be removed. The words MRKHotels / Portal / Dashboard / My Profile / Logout / EN-SW should be moved into the profile at TOP RIGHT CORNER which will have a circle profile with user’s PROFILE PICTURE if not let it be initials of their registered names. Right next to the profile circle add a NOTIFICATION BADGE BELL. DASHBOARD should be removed completely.”
The hotel contact strip was removed from the staff panel. The top-right corner now has the circle profile (initials only, e.g. AL) and a notification bell beside it. Clicking the profile opens Portal, User Manual, My Profile, Log Out and the language switch (EN / SW). The Dashboard link and the duplicated side-bar account links were removed.
Status: DONE
→ Dashboard > Top Bar (Right Side) > Bell + Circle Profile (Initials)

6. DUE OUT CONDITIONS BYPASSED

“Upon testing it has occurred once again where DUE OUT color change conditions has been bypassed. Example the user performed night audit of 08/10/2026 therefore the guest SWAUM HAMIS should automatically turn to purple indicating this room is due out therefore night audit for 09/10/2026 would be blocked unless the guest SWAUM HAMIS is checked out. Fix this error.”
A checked-in guest whose checkout day has arrived or already passed now stays on the board and turns purple (Due Out) — previously an overdue guest dropped off the board or turned green once the business date rolled past their checkout. The Due Out and Occupied counts, and the guests-in-house figure, now include them, and the night audit still blocks while any overdue guest has an unsettled bill, exactly as the example requires.
Status: DONE
→ Dashboard > Rooms Chart > Overdue Stay Shown Purple (Due Out)

7. DUE OUT FOLIO OPERATIONS FLAW

“When room status changes to due out it seems to affect the amount due of the guest either to be paid or to be posted to creditors. Why does this happen? TO FIX — ensure the balance due matches the exact amount that should be payable upon adding payments.”
The amount offered in Post to Creditors and Collect Payment (and the over-payment guard) now reads the same ledger balance shown on the folio — charges minus payments. It no longer reads the separate backend header figure that shifted when a guest was carried past checkout as a due-out. The amount payable and the balance due therefore always agree, whatever the room status.
Status: DONE
→ Dashboard > Open Stay > Folio Operations > Balance / Post To Creditors
